# 软件工程

软件工程是综合知识和案例分析的共同基础。学习重点不是背诵模型名称，而是理解每种方法解决什么问题、承担什么代价。

## 生命周期模型

| 模型 | 适用场景 | 主要风险 |
| --- | --- | --- |
| 瀑布模型 | 需求稳定、过程规范 | 反馈晚，变更成本高 |
| 原型模型 | 需求不清晰、强调交互 | 原型被误当作正式系统 |
| 增量模型 | 需要分批交付价值 | 整体架构容易被局部需求侵蚀 |
| 螺旋模型 | 大型、高风险项目 | 管理复杂、成本较高 |
| 敏捷方法 | 需求变化快、反馈频繁 | 依赖团队协作与持续工程能力 |

## 需求工程

需求工程包括获取、分析、规格说明、验证和管理。案例题中应区分业务目标、用户需求、功能需求和非功能需求。

### 需求验证

- 正确性：需求是否反映真实意图。
- 完整性：是否遗漏必要功能与约束。
- 一致性：需求之间是否冲突。
- 可验证性：是否能通过测试或度量确认。
- 可追踪性：是否能关联来源、设计、实现与测试。

## 内聚与耦合

设计目标通常是高内聚、低耦合。内聚从高到低可记为：功能、顺序、通信、过程、时间、逻辑、偶然。答题时不仅写类型，还要结合职责和数据关系说明判断依据。

## 软件测试

黑盒测试关注输入输出，包括等价类、边界值、判定表和因果图；白盒测试关注内部逻辑，包括语句、分支、条件和路径覆盖。
