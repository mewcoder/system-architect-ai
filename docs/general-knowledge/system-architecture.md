# 系统架构设计

系统架构设计连接业务目标、质量属性与技术决策。考试既考概念，也考在具体约束下如何选择方案。

## 质量属性

质量属性场景通常由刺激源、刺激、环境、制品、响应和响应度量组成。

| 属性 | 常用策略 |
| --- | --- |
| 性能 | 缓存、并发、资源池、减少计算开销 |
| 可用性 | 冗余、故障检测、故障恢复、降级 |
| 安全性 | 认证、授权、审计、加密、最小权限 |
| 可修改性 | 局部化修改、抽象接口、延迟绑定 |
| 可测试性 | 控制与观察状态、隔离依赖、自动化 |

## 4+1 视图模型

- 逻辑视图：描述关键抽象和功能分解。
- 开发视图：描述代码组织与模块关系。
- 进程视图：描述并发、同步和运行时行为。
- 物理视图：描述软件到硬件节点的映射。
- 场景视图：用用例串联并验证其他视图。

## 常见架构风格

| 风格 | 优点 | 局限 |
| --- | --- | --- |
| 分层 | 职责清晰、易替换 | 跨层调用带来开销 |
| 管道过滤器 | 易组合、易复用 | 不适合强交互状态 |
| 事件驱动 | 解耦、易扩展 | 调试与一致性复杂 |
| 微服务 | 独立部署、弹性伸缩 | 分布式治理成本高 |
| 微内核 | 核心稳定、插件扩展 | 接口设计要求高 |

## 架构评估

ATAM 以质量属性场景为基础，识别敏感点、权衡点、风险与非风险。案例作答应明确：业务驱动因素、候选方案、质量属性影响、风险和最终权衡。
