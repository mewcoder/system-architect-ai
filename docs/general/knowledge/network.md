## 1. 网络基础与通信

先用分层模型建立地图，再把信号、交换和介质放回对应层次。OSI 与 TCP/IP 的题目重点是职责边界：物理层处理信号和介质，数据链路层负责相邻节点之间的帧传输，网络层负责跨网络寻址与转发，传输层面向进程提供端到端通信，应用层承载具体网络服务。

| 主题 | 重点 |
| --- | --- |
| 物理层接口 | 机械、电气、功能、过程四类特性 |
| 数据通信 | 电路交换、分组交换、半双工与全双工 |
| 信号处理 | 调制解调、奈奎斯特采样定理、奈奎斯特定律、香农公式 |
| 基带编码 | 曼彻斯特编码具备自同步能力；要区分编码和差错控制 |
| 综合布线 | 工作区、水平、干线、管理、设备间、建筑群六个子系统 |

计算题先看条件：理想无噪声信道用奈奎斯特定律，有噪声信道用香农公式；采样题判断“采样频率至少是最高频率的两倍”。交换方式题则抓住 Internet 采用分组交换，数据被拆成分组后通过存储转发完成传输。

## 2. 网络协议与服务

这一章把数据链路层、网络层、传输层和应用层放在一条通信链路上理解：数据链路层负责相邻节点之间的帧传输，网络层负责跨网络寻址与转发，传输层面向进程提供端到端通信，应用层提供 DNS、DHCP、电子邮件和 Web 等具体服务。

数据链路层常考成帧、差错检测、透明传输、流量控制和介质访问控制。交换机根据源 MAC 地址学习转发表，目的地址已知时定向转发，未知时向除入端口外的端口洪泛；长期不用的表项会老化。二层交换机工作在数据链路层，三层交换机还可以承担网络层转发。

无线与移动网络可以抓住三组对比：<strong>WEP</strong> 是早期方案，<strong>WPA</strong> 是改进方案，<strong>WPA2</strong> 基于 IEEE 802.11i 并使用 AES；802.11b 工作在 2.4GHz，典型速率最高为 11Mbps；5G 网络切片是在同一物理基础设施上划分相互逻辑隔离的端到端虚拟网络。

IPv4 地址题先把掩码转换为网络位和主机位。主机位为 `n` 位时，常规子网可用主机地址数为 `2^n-2`，要注意题目是否给出点到点链路等特殊使用场景。IPv6 地址长度为 128 位，支持单播、组播和任播；链路本地地址以 FE80::/10 开头。管理距离越小，路由来源可信度越高；DiffServ 依据 IP 头中的服务类型字段设置 DS 码点，再按标记调度转发。

传输层先做 TCP 与 UDP 的定位：TCP 面向连接、可靠有序，UDP 无连接、开销较小，更适合实时性优先的场景。TCP 端口号用于把数据交给主机上的具体应用进程，与 IP 地址共同构成套接字。

| 服务 | 重点 |
| --- | --- |
| DNS | A 记录完成域名到 IP 的正向解析，PTR 记录完成 IP 到域名的反向解析 |
| DHCP | Discover、Offer、Request、Ack/Decline/Nack 分别承担发现、提供、请求和确认/拒绝等作用 |
| 电子邮件 | SMTP 负责发送，常见端口为 25；POP3 常见端口为 110；IMAP 常见端口为 143 |
| Web | HTTP 默认 80 端口；HTTPS 在 HTTP 之上引入 SSL/TLS，默认 443 端口 |

浏览器访问 Web 页面时，通常先完成域名解析，再完成 ARP 寻址和 TCP 连接建立，之后才发送 HTTP 请求。网络异常题关注重连、超时、心跳和退避重试，并要防止无上限重连放大故障。反向 DNS 解析题要区分域名到 IP 的正向解析和 IP 到域名的 PTR 记录；遇到管理距离和路由代价，则先判断是在比较不同路由来源，还是在比较同一路由协议内部的路径优劣。

## 3. 网络规划与设计

网络规划题从需求出发，再区分逻辑设计和物理设计。需求分析关注总体需求、综合布线、可用性与可靠性、安全性和工程造价；逻辑设计关注拓扑、地址、子网和服务规划；物理设计落实设备、布线、安装测试和培训。

局域网三层设计按<strong>接入层 → 汇聚层 → 核心层</strong>理解：接入层连接终端，汇聚层承担流量汇聚和策略控制，核心层强调高速、可靠和冗余转发，不宜堆叠复杂策略。连续地址空间可以支持路由汇总，减少上级路由器维护的明细路由数量。

其他高频判断点：

- 层次化设计要保持模块边界和层次关系，不能因为增加跨层连接而破坏整体结构。
- 冗余设计解决容错和单点故障，负载分担解决并行链路的资源利用，二者可以组合但概念不同。
- 网络延迟包括处理、排队、发送和传播延迟；分析题干时要找具体瓶颈。
- SDN 采用控制平面与转发平面分离的思路，应用层通过控制器使用网络能力。
- IntServ 按数据流提供 QoS，DiffServ 按业务类别或标记进行较粗粒度的差异化服务。

## 4. 网络安全与网络存储

网络安全协议要放回应用场景和协议层次中比较：SSL/TLS 位于传输层之上，为 HTTP、SMTP 等应用协议提供认证、加密和完整性保护；S/MIME 面向安全电子邮件；Kerberos 依赖 KDC、认证服务器和票据授予服务器完成身份认证与单点登录。

| 主题 | 判断线索 |
| --- | --- |
| SSL/TLS | 有保密性、可靠性和完整性；不可抵赖性通常依赖数字签名，不能直接算作 SSL 的特性 |
| 邮件安全 | S/MIME、PGP 等用于加密或签名；MIME 本身主要解决附件和非 ASCII 内容传输，不等于安全协议 |
| 协议分层 | HTTPS、SSH、S/MIME 属于应用层安全协议；IPSec 主要提供网络层保护 |
| RAID5 | 至少三块盘，校验信息分布存储；容量按“盘数减一”乘以最小单盘容量估算 |
| 倒排索引 | 以词项映射到文档列表，适合搜索和全文检索 |

做这类题时先识别“保护对象”或“数据组织方向”：是通信保密、身份认证、邮件内容保护，还是存储冗余与检索效率，通常就能排除跨领域干扰项。
