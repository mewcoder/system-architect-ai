# 信息化与企业信息系统

信息化不是简单地“把纸面流程搬到电脑里”。它是一项从战略、业务、数据、组织到技术基础设施的系统性变革：企业利用信息技术开发和利用信息资源，重组业务流程和管理方式，最终提升运营效率、决策能力与竞争力。

可以先记住一句话：

> 信息化以信息资源为核心，以业务价值为牵引，以信息系统为载体，以组织、制度和技术治理保证落地。

## 一、信息化的基本概念

### 信息系统是什么

信息系统是由硬件、网络与通信设备、软件、信息资源、用户以及规章制度共同组成的人机系统，目标是收集、存储、处理、传输和使用信息。

它有五项基本功能：

| 功能 | 作用 |
| --- | --- |
| 输入 | 采集业务数据、用户请求和外部信息 |
| 存储 | 保存数据、文档、模型和知识 |
| 处理 | 对数据进行计算、分析、转换和挖掘 |
| 输出 | 形成报表、消息、决策依据或业务结果 |
| 控制 | 对处理、传输、权限和运行过程进行约束 |

信息系统不是“计算机加软件”的同义词。计算机只是技术基础，用户、业务规则、信息资源和管理制度同样属于系统的一部分。

### 信息化是什么

广义的信息化，是在信息政策指导下，依托网络、通信和计算等技术，开发利用信息资源、发展信息产业、培养信息人才，并推动社会组织和运行方式变化的过程。

国家信息化通常可以从六个要素理解：

1. 开发和利用信息资源。
2. 建设信息网络体系。
3. 推进信息技术应用。
4. 发展信息技术和信息产业。
5. 培育信息化人才。
6. 制定和完善信息化政策、法规与标准。

因此，信息化既是技术建设，也是生产方式、组织关系和治理方式的变化。

## 二、信息系统的发展规律

教程用诺兰模型描述组织信息系统的发展过程，六个阶段具有明显的演进关系：

| 阶段 | 典型表现 | 主要问题或转变 |
| --- | --- | --- |
| 初始 | 少数部门使用计算机处理报表 | 应用范围小，主要是工具替代 |
| 传播 | 应用需求快速增加，部门纷纷建设系统 | 数据冗余、不一致、难共享 |
| 控制 | 开始统一管理 IT 投资和系统建设 | 出现数据库，但仍有部门壁垒 |
| 集成 | 建设基础数据库和统一信息系统 | 从分散建设转向体系化建设 |
| 数据管理 | 统一数据库、数据平台和管理体系 | 信息资源成为组织的重要资产 |
| 成熟 | IT 与管理、业务和外部资源深度结合 | 支持管理决策和企业竞争 |

这个模型的关键启示是：组织不能长期停留在“各部门各自买系统”的阶段。信息化建设需要从单点应用逐步走向统一规划、数据共享、系统集成和战略协同。

## 三、企业信息化的目标与实施逻辑

### 企业信息化的目标

企业信息化表现为四种能力的提升：

- 生产过程自动化。
- 管理方式网络化。
- 决策支持智能化。
- 商务运营电子化。

它的根本目的不是建设更多系统，而是提高企业竞争能力，使企业能够稳定运行、快速响应市场变化，并持续为内部和外部用户提供有价值的信息。

企业信息化通常会带来三类创新：

| 创新类型 | 关注重点 |
| --- | --- |
| 技术创新 | 用信息技术改进研发、设计、生产和技术成果转化 |
| 管理创新 | 重组财务、生产、供应链、客户和人力资源等管理流程 |
| 制度创新 | 调整组织职责、岗位责任、监管机制和管理制度 |

### 自上而下与自下而上

企业信息化需要两个方向同时推进：

- 自上而下：从企业战略、组织和管理制度出发，明确为什么建设、建设什么以及优先级是什么。
- 自下而上：从业务人员的实际工作出发，让系统真正解决业务问题，并通过持续使用形成应用效果。

只有战略目标而没有业务使用，容易形成“领导要求建设、员工不愿使用”；只有局部业务需求而没有整体规划，又容易形成新的信息孤岛。

### 企业信息化的三个融合层面

1. **企业战略层面**：分析企业战略、未来方向、供应链和管理模式，识别信息技术的驱动因素。
2. **业务运作层面**：识别创造价值的关键流程，由关键流程推导系统功能和业务需求。
3. **管理运作层面**：支撑日常管理的规范化和高效化，同时提出应用功能与技术体系要求。

这三个层面可以浓缩为一条主线：

> 战略决定方向，业务流程决定系统价值，管理与技术决定能否稳定运行。

## 四、企业中常见的信息系统

不同类型的信息系统不是相互替代的关系，而是可以组合和融合，覆盖从事务处理到战略决策的不同层次。

| 系统 | 核心作用 | 典型关注点 |
| --- | --- | --- |
| TPS/DPS | 处理日常业务和事务数据 | 订单、销售、财务、库存、生产记录 |
| MIS | 为企业管理提供综合信息 | 信息汇总、内部管理、跨业务联系 |
| DSS | 支持半结构化和非结构化决策 | 数据、模型、分析方法和交互 |
| ES | 用专家知识解决领域问题 | 知识库、推理、判断和经验复用 |
| OAS | 提升办公事务处理效率 | 文档、通信、流程、协同办公 |
| ERP | 综合管理企业资源 | 财务、采购、生产、销售、供应链和人力 |

在制造和企业运营中，还常见以下系统：

- **WMS**：仓储货位、收发料、库存、盘点和出库管理。
- **MES**：生产过程、工艺、设备、质量和现场管控。
- **PDM**：研发阶段的产品数据、物料、BOM 和工程变更管理。

理解这些系统时，重点不是背缩写，而是判断它们管理的对象和所处的业务环节：ERP 偏企业资源协同，WMS 偏仓储，MES 偏生产现场，PDM 偏产品研发数据。

## 五、企业信息系统的总体架构

企业信息系统架构不是某一个软件的技术方案，而是对企业战略、业务、应用、数据和基础设施关系的整体描述。教程中的总体框架可以从四个方面理解：

1. **战略系统**：承接企业使命、目标、战略和经营方向。
2. **业务系统**：描述组织、业务流程、价值链和管理活动。
3. **应用系统**：把业务要求落成 ERP、办公、生产、供应链、客户等应用。
4. **信息基础设施**：提供计算、存储、网络、数据库、安全和运行环境。

四个方面可以进一步对应管理金字塔：战略管理、战术管理和运行管理。架构设计的任务，是让不同层次之间能够传递目标、流程、数据和控制要求，而不是让每个系统单独优化。

### 物理结构与逻辑结构

- **物理结构**关注硬件和资源在空间上的组织方式，常见有集中式和分布式。
- **逻辑结构**关注功能子系统、数据、程序和它们之间的关系。

集中式结构便于统一管理，但存在单点故障和扩展困难；分布式结构更适合现代企业的网络化和多地点协同，但需要解决标准统一、资源协调和治理复杂度问题。

### 信息系统的综合

企业系统不能只看单个部门或单个应用，还需要进行：

- **横向综合**：整合同一管理层次上的多个职能。
- **纵向综合**：打通同一职能在不同管理层级之间的联系。
- **纵横综合**：同时统一信息模型和处理模型，建设共享数据与公共服务。

## 六、常见架构模型

### 单机应用

所有主要功能集中在一台物理机器上，结构简单、部署直接，但共享能力、扩展能力和协同能力有限。

### 客户机/服务器

客户端发起服务请求，服务器提供数据或业务服务。两层 C/S 常见于“前台界面 + 后台数据库”，多层 C/S 则进一步把表示、业务逻辑和数据服务分开。

### MVC

将表示、业务模型和控制逻辑分离，降低界面变化对业务逻辑的影响，适合需要多种界面或持续演化的应用系统。

### SOA 与企业服务总线

把可复用的业务能力封装为服务，通过服务组合和消息/事件交换支撑跨系统流程。企业服务总线可以提供传输、路由、事件发布订阅和系统适配能力，减少遗留系统之间的点对点耦合。

## 七、信息化建设的方法与生命周期

### 两种信息化架构思路

#### 数据导向架构

从主题域、业务对象和对象关系入手，建立概念模型、逻辑模型和物理模型，再管理数据的产生、变更、共享和废弃。它适合数据中心、商业智能、主数据和数据质量建设。

#### 流程导向架构

从价值链、端到端流程和业务组件入手，识别可复用服务，通过流程编排完成业务整合。它适合跨部门协同、服务组合和流程自动化。

两者并不互相排斥。SOA 擅长流程整合，但不能独立解决数据存储和数据质量问题；主数据管理擅长统一数据视图，但需要借助服务能力进行数据分发和实时协同。企业通常需要让二者结合。

### 常见信息化建设方法

- **业务流程重构**：重新审视组织结构和工作方式，用信息技术支持根本性的流程优化。
- **核心业务应用**：优先围绕企业最关键、最能创造竞争优势的业务建设系统。
- **信息系统建设**：通过建设应用系统承载企业的信息化目标。
- **主题数据库**：围绕核心业务主题建设共享数据库，减少部门各自开发造成的信息孤岛。
- **资源管理**：通过 ERP、SCM 等方式统筹企业资源和供应链。
- **人力资本投资**：重视人才、知识和组织能力，尤其适合知识密集型企业。

### 信息化建设生命周期

从工程建设角度，可以把信息化过程理解为五个阶段：

1. **系统规划**：调查企业环境、目标和现状，分析需求与可行性，确定建设战略和备选方案。
2. **系统分析**：调查现行业务，梳理流程、数据和功能，形成新系统的逻辑模型。
3. **系统设计**：回答“怎么做”，形成总体设计、详细设计和技术方案。
4. **系统实施**：完成设备部署、程序开发、数据转换、培训、测试和系统切换。
5. **运行与维护**：持续运行、评价、修改和演进，直到系统被更新或替代。

这与“产生—开发—运行—消亡”的宏观生命周期并不矛盾：前者关注建设活动，后者关注系统从诞生到退出的完整生存过程。

## 八、信息化总体规划的三种方法

### 关键成功因素法（CSF）

从组织目标出发，识别真正影响目标实现的关键因素，再确定所需信息、性能指标和系统开发优先级。

它擅长抓住主要矛盾、快速明确重点，但容易受到当前阶段和管理者视角的影响。

### 战略目标集转化法（SST）

把组织的使命、目标和战略看作一个目标集合，再将其系统地转化为信息系统的战略目标。

它覆盖面较广、完整性较好，适合保证信息化方向与组织战略一致。

### 企业系统规划法（BSP）

自上而下识别企业目标、业务过程和数据，再自下而上设计信息系统。它强调企业过程、数据类和系统之间的结构化分析，适合形成面向全企业的一致性规划。

三种方法可以这样记：

| 方法 | 记忆重点 |
| --- | --- |
| CSF | 找关键点，确定优先级 |
| SST | 把组织战略转成信息系统战略 |
| BSP | 识别过程和数据，再规划系统 |

## 九、TOGAF/ADM 的架构开发思路

TOGAF 是开放式企业架构框架，ADM 是其中最核心的架构开发方法。它不是一次性画完架构，而是围绕业务需求进行迭代，并持续更新架构资源库。

ADM 的主要阶段可以概括为：

1. 准备：建立架构能力、原则、组织和治理基础。
2. 需求管理：持续识别、记录、排序和变更管理需求。
3. 架构愿景：明确范围、目标、干系人和预期价值。
4. 业务架构：描述组织、业务能力、流程和业务目标。
5. 信息系统架构：分别设计数据架构和应用架构。
6. 技术架构：确定支撑应用和数据的技术平台、基础设施与标准。
7. 机会与解决方案：识别实现路径、项目组合和过渡架构。
8. 迁移规划：安排优先级、路线图、成本和实施计划。
9. 实施治理：在落地过程中进行架构合规、协同和决策控制。
10. 架构变更管理：监控环境和业务变化，触发下一轮架构演进。

其中，需求管理贯穿全部阶段；架构变更管理保证架构不会因为环境变化而失效。

## 十、电子政务与企业电子商务

### 电子政务

电子政务是利用信息技术改造政府组织结构和工作流程，减少时间、空间和部门分隔，实现政府管理与公共服务的网络化。

它主要体现为：

- 政府内部电子化、网络化办公。
- 政府部门之间的信息共享和实时通信。
- 政府与企业、居民之间的在线互动和服务。

常见的互动关系包括政府对政府、政府对企业、政府对居民、企业对政府和居民对政府。发展成熟度通常经历信息发布、单向互动、双向互动和网上事务处理。

### 企业电子商务

电子商务是企业信息化在商务运营层面的延伸。它不仅是搭建一个交易网站，还涉及客户、订单、支付、供应链、物流、服务和内部管理等流程的协同。

因此，电子商务能否持续发挥作用，取决于企业内部的信息系统、数据资源和业务流程是否能够支撑前台业务。

## 十一、案例带来的架构启示

教程中的企业整合案例可以提炼出几条通用经验：

1. 先理解业务流程，再决定服务和系统边界。
2. 把遗留系统中的数据和能力封装成较粗粒度的业务对象或信息服务。
3. 把多个流程共享的业务活动抽象为可复用服务。
4. 用事件服务和发布/订阅减少系统间的点对点连接。
5. 通过流程服务编排多个服务，支撑不同业务场景的组合。
6. 通过适配器隔离旧系统协议和新系统服务，降低改造风险。
7. 让服务可以替换和演进，避免一次改动牵连整个系统。

这说明企业架构的价值不只是“把系统画出来”，而是用稳定的业务、数据和服务抽象，帮助企业在保留既有资产的同时持续变化。

## 十二、学习时的总线索

可以用下面这条链路复习信息化知识：

> 战略目标 → 关键业务流程 → 业务能力与数据 → 应用系统 → 技术基础设施 → 实施治理 → 持续演进

最后再抓住四个判断标准：

- 有没有服务企业战略，而不是只解决局部技术问题？
- 有没有围绕关键业务流程创造价值？
- 有没有统一数据、减少信息孤岛？
- 有没有考虑组织、制度、治理和持续变更？

能沿着这条链路把概念串起来，信息化、企业架构、信息系统规划和 SOA 等知识点就不再是孤立的术语，而会形成一套完整的企业数字化建设思路。
