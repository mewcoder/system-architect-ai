# 信息安全

教材第 4 章把信息安全分为基础知识、信息系统安全体系、加解密、访问控制与数字签名、抗攻击，以及保障体系与风险评估。本页将这些内容压缩为六个学习章节，并把已经提取的真题放到对应位置。

## 1. 安全基础

### 1.1 五个基本要素

教材将信息安全概括为五个基本要素：<strong>机密性、完整性、可用性、可控性和可审查性</strong>。

| 要素 | 判断重点 |
| --- | --- |
| 机密性 | 信息不暴露给未授权的实体或进程 |
| 完整性 | 数据只能由得到允许的人修改，并且能够发现数据是否被篡改 |
| 可用性 | 授权实体在需要时可以访问数据和服务 |
| 可控性 | 能够控制授权范围内的信息流向和行为方式 |
| 可审查性 | 出现安全问题后，可以提供调查、追踪和取证依据 |

题目中的“信息泄露”通常对应<strong>机密性</strong>，“数据被修改或破坏”对应<strong>完整性</strong>，“合法访问被阻止”对应<strong>可用性</strong>；出现争议时能够回放通信过程、确认收发方身份，则与<strong>可审查性和抗抵赖</strong>有关。

### 1.2 信息安全的范围

信息安全的保护范围可以从四个方面理解：

- <strong>设备安全</strong>：关注设备的稳定性、可靠性和可用性，是信息系统安全的物质基础。
- <strong>数据安全</strong>：保护数据的秘密性、完整性和可用性，防止未授权泄露、篡改和毁坏。
- <strong>内容安全</strong>：关注信息内容在政治、法律和道德层面的合规性。
- <strong>行为安全</strong>：保证系统行为的秘密性、完整性和可控性，使行为过程和结果符合预期。

### 1.3 网络安全威胁

教材归纳的典型网络威胁包括：非授权访问、信息泄露或丢失、破坏数据完整性、拒绝服务攻击，以及利用网络传播病毒。安全措施的目标可以归纳为<strong>访问控制、认证、完整性、审计和保密</strong>。

## 2. 安全体系

### 2.1 信息系统安全的组成

信息安全不是单一技术，而是由三类体系共同构成：

| 体系 | 主要内容 |
| --- | --- |
| 技术体系 | 基础安全设备、网络安全、操作系统安全、数据库安全和终端安全等 |
| 组织机构体系 | 决策层、管理层和执行层，以及相应的安全岗位和人员管理 |
| 管理体系 | 法律管理、制度管理和培训管理 |

教材强调，技术措施需要组织和管理配合才能真正落地。可以把它概括为：<strong>技术负责防护，组织负责落实，管理负责约束和持续改进</strong>。

### 2.2 数据安全治理

近年真题还会从数据全生命周期考查安全治理。当前题库中出现的治理目标包括：<strong>满足合规要求、管理数据安全风险、促进数据开发利用</strong>。

从治理视角看，可以把安全工作分为三层：

- <strong>战略层</strong>：确定数据安全目标、方向和责任。
- <strong>全生命周期安全层</strong>：覆盖数据生成、存储、传输、加工使用和销毁等阶段。
- <strong>基础安全层</strong>：提供网络、主机、物理环境和技术工具等支撑。

## 3. 加密技术

### 3.1 保密通信模型

发送方使用加密算法和密钥把明文转换为密文，接收方使用解密算法和密钥恢复明文。教材中的基本关系是：

```text
密文 C = E(K, P)
明文 P = D(K, C)
```

其中，算法可以公开，真正需要保护的是<strong>密钥 K</strong>。

### 3.2 对称与非对称加密

| 类型 | 密钥关系 | 典型用途 | 题目抓手 |
| --- | --- | --- | --- |
| 对称加密 | 加密密钥和解密密钥相同 | 大量数据加密 | DES、3DES、AES |
| 非对称加密 | 加密密钥和解密密钥不同 | 保密通信、密钥交换、数字签名 | RSA、公钥、私钥 |

教材中的高频算法记忆点：

- <strong>DES</strong>使用 56 位密钥。
- <strong>三重 DES</strong>使用两把独立密钥时，有效密钥长度通常为 112 位。
- <strong>AES</strong>支持 128、192 和 256 位密钥长度。
- 使用<strong>公钥加密、私钥解密</strong>，主要用于保密通信；使用<strong>私钥形成签名、公钥验证</strong>，主要用于数字签名。
- RSA 的安全性建立在大数分解困难的基础上。

### 3.3 密钥管理与 PKI

对称密钥管理中，常见做法是由密钥分配中心（KDC）为用户分配会话密钥。<strong>主密钥</strong>用于保护分配过程，<strong>会话密钥</strong>用于一次通信，会话结束后可以销毁。用户数量较多时，KDC 可以减少需要人工分配和长期保存的主密钥数量。

公钥管理的安全性依次取决于公钥发布、公用目录、公钥管理机构和<strong>公钥证书</strong>等机制。公钥证书由 CA 签发，通常包含用户身份、公钥和时间戳等信息，并由 CA 使用自己的私钥签名，接收方使用 CA 公钥验证证书。

### 3.4 哈希与数字签名

长文件通常不直接进行完整的公钥签名，而是先计算文件的单向 Hash 值，再对摘要进行签名。这样可以减少计算和存储开销，并能在发生争议时通过摘要验证文件是否发生变化。

数字签名主要提供三类能力：

- 接收方可以验证消息确实来自发送方；
- 发送方不能否认已经发送过消息；
- 接收方不能在不被发现的情况下修改消息。

## 4. 访问控制

### 4.1 访问控制模型

访问控制的目标是保护信息系统中存储和处理的信息，基本模型包含三个要素：

| 要素 | 含义 |
| --- | --- |
| 主体（Subject） | 发起访问或施加动作的主动实体，例如用户、终端、程序或进程 |
| 客体（Object） | 被访问的被动实体，例如文件、记录、信息或设备 |
| 控制策略 | 规定主体可以对客体执行哪些操作，以及适用的约束条件 |

访问控制的实现通常包括<strong>认证、控制策略实现和审计</strong>三个方面。先确认主体身份，再根据策略判断权限，最后记录重要行为并检查是否存在越权操作。

### 4.2 访问控制的实现

访问控制矩阵（ACM）用矩阵表示主体、客体和访问权限：<strong>行表示主体，列表示客体，单元格表示访问方式</strong>。

矩阵在大型系统中会很大，因此实际常用其变形：

- <strong>访问控制表（ACL）</strong>：按客体保存，适合查询“谁可以访问这个客体”。
- <strong>能力表（Capabilities）</strong>：按主体保存，适合查询“这个主体可以访问哪些客体”。
- <strong>授权关系表</strong>：只保存访问矩阵中非空的授权关系，可按主体或客体排序。

## 5. 攻击防护

### 5.1 常见攻击

教材重点介绍密钥选择、拒绝服务攻击、欺骗攻击、端口扫描、TCP/IP 堆栈防护和系统漏洞扫描。

| 类型 | 核心判断 |
| --- | --- |
| 拒绝服务攻击 | 消耗服务端资源，使正常用户无法获得服务；DDoS 是分布式形式 |
| SYN Flooding | 利用 TCP 三次握手产生大量半连接，耗尽服务器连接和处理资源 |
| 欺骗攻击 | 伪造身份或地址，例如 IP 欺骗、DNS 欺骗 |
| 端口扫描 | 通过尝试连接端口，判断目标主机开放的服务和可能使用的操作系统 |
| SQL 注入 | 将恶意输入拼接进 SQL 语句，改变原有查询或操作逻辑 |

### 5.2 漏洞扫描

漏洞扫描用于发现可能被攻击者利用的系统弱点。教材按扫描位置分为：

- <strong>基于网络的扫描</strong>：从网络远程探测目标，不需要在目标系统安装代理，部署和维护相对方便。
- <strong>基于主机的扫描</strong>：在目标系统安装代理或服务，可以访问更多文件和进程，通常能够发现更多漏洞，但部署成本更高。

防护题一般要先判断攻击利用的对象，再判断它造成的安全属性损害：DDoS 主要影响<strong>可用性</strong>，篡改数据主要影响<strong>完整性</strong>，窃取信息主要影响<strong>机密性</strong>。

## 6. 安全保障

### 6.1 安全保护等级

教材依据 GB 17859—1999，将计算机信息系统安全保护能力划分为五个等级，由低到高分别是：

1. 用户自主保护级
2. 系统审计保护级
3. 安全标记保护级
4. 结构化保护级
5. 访问验证保护级

记忆时重点关注两个方向：等级越高，访问控制越严格；同时对审计、强制访问控制、抗渗透、系统恢复等能力的要求也逐步增强。

### 6.2 安全风险管理

信息安全风险来自<strong>资产、威胁和脆弱性</strong>之间的关系。威胁利用脆弱性作用于资产，形成安全事件和影响；安全需求通过安全措施得到满足，但安全措施实施后仍可能存在残余风险。

风险评估主要关注：

- 评估范围和目标；
- 资产价值及其机密性、完整性、可用性影响；
- 面临的威胁和系统脆弱性；
- 安全事件发生的可能性和影响；
- 安全措施、实施成本和残余风险。

按实施者不同，风险评估可分为<strong>自评估</strong>和<strong>他评估</strong>。前者由系统拥有者依靠自身力量开展，后者通常由上级或业务主管机关发起，依据法规或标准实施。
