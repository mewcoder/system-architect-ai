# 操作系统

本页按操作系统 JSON 中的真题分布建立知识结构。一级章节保留题库中最稳定的分类；前趋图并入进程管理，操作系统分类并入进程管理；同一道题的多个分值记录仍按原题保留。

本模块共有<strong>71 道真题</strong>、<strong>83 条分值记录</strong>；近 4 场考试覆盖 21 道不同题号。

## 1. 进程管理

进程管理先抓住“状态、调度、同步、通信、死锁”这条主线。三态模型通常围绕运行、就绪和阻塞之间的转换判断：时间片用尽或被高优先级进程抢占，运行态会回到就绪态；等待 I/O 或资源则进入阻塞态。

| 主题 | 重点 |
| --- | --- |
| 进程与线程 | 进程是资源分配和管理的基本单位；同一进程的线程共享进程资源，但有各自的执行状态 |
| 调度 | 关注先来先服务、优先级、时间片和抢占；实时任务还要结合截止时间判断 |
| 同步互斥 | 临界资源、互斥信号量、PV 操作和共享数据结构 |
| 进程通信 | 消息、共享内存等方式解决任务之间的信息交换与协同 |
| 死锁 | 识别等待关系、预防方法和安全资源数量；资源分配题要先列出进程最大需求 |

前趋图题可以看成“任务之间的完成先后约束”：边表示前置任务完成后，后继任务才能开始。PV 题要把每条依赖关系对应到信号量的等待和释放操作，不要只凭图形位置猜选项。操作系统分类题则结合批处理、分时和实时系统的调度目标判断。

## 2. 内存管理

内存管理题主要围绕地址转换和分配方式展开。分页把虚拟地址和物理地址划分为页与页框，页表负责记录映射；分段按逻辑段组织地址空间；段页式则同时保留分段的逻辑结构和分页的物理管理方式。

| 主题 | 解题抓手 |
| --- | --- |
| 分页 | 先用页面大小拆出页号和页内地址，再查页表得到物理页号 |
| 分段 | 判断段号是否存在、段内偏移是否越界，以及段表给出的权限和长度 |
| 段页式 | 先定位段，再在段内查页，最后拼接页框号和页内偏移 |
| 位示图 | 用“管理对象数量 ÷ 字长”计算位示图占用的字数或空间 |
| 地址转换 | 区分逻辑地址、虚拟地址、物理地址、页号、页框号和页内偏移 |

计算题不要直接套结果：先确定页面或段的大小，再拆地址；遇到状态位为 0 的页，要判断题目是在考缺页，还是只要求指出当前映射不可直接完成。

## 3. 文件系统

文件系统题重点是文件如何命名、组织和定位。索引节点法把文件的物理块地址集中放在索引节点中，直接地址、一级间接地址和二级间接地址会影响文件最大长度；多级索引题要先算一个索引块能容纳多少个块号，再逐级展开。

| 主题 | 高频判断点 |
| --- | --- |
| 路径 | 绝对路径从根目录开始；相对路径依赖当前目录 |
| 文件分配 | 随机访问可变长文件时，要重点比较定位能力与空间连续性 |
| 索引结构 | 直接索引适合小文件，间接索引扩大可寻址文件范围 |
| 目录项 | 目录项由索引信息和文件名等内容组成，按编址方式计算可表示数量 |
| 文件操作 | 打开文件通常需要读取目录项并建立相应的打开文件信息 |

位示图、页面分配和文件块分配的题干都可能出现“位”的计算，但管理对象不同：要先判断它描述的是主存页面、磁盘物理块还是文件索引，再选择公式。题库中 XML 和内核功能题也保留在原始“文件系统”分类下，页面不改变题目原分类。

## 4. 磁盘管理

磁盘管理题围绕“寻道、旋转、传输和缓冲”分析 I/O 时间。磁盘调度通常先进行移臂调度，再考虑旋转调度；最短移臂算法要根据当前磁头位置逐步选择距离最近的请求。

双缓冲题要把磁盘读入缓冲区、缓冲区送入用户区和系统处理三个时间段分开，判断并行工作时的吞吐量瓶颈。磁盘记录的排列顺序也会影响旋转等待和 I/O 总时间，不能只看记录总数。

文件首次打开、磁盘位图和磁道扇区计算题，仍然要先明确管理对象：是文件控制信息、磁盘块占用情况，还是磁盘物理几何参数。

## 5. 嵌入式系统

嵌入式系统题以资源约束、实时性和硬件相关性为核心。与通用操作系统相比，嵌入式系统更关注确定性响应、低功耗、启动和存储资源限制，以及软件对具体硬件平台的适配。

| 主题 | 重点 |
| --- | --- |
| 实时系统 | 事件必须在规定时间内得到处理；强实时系统要求任务在截止时间前完成 |
| 调度算法 | 按到达顺序、截止期和优先级等条件选择任务；题目要先判断是否允许抢占 |
| BSP | 板级支持包向上层屏蔽硬件差异，提供与具体板卡相关的启动和设备支持 |
| 可靠与低功耗 | 看门狗用于监测异常运行，软件低功耗要结合处理器和外设的使用方式 |
| 系统接口 | RTOS 内核与应用程序之间通过规定的接口协作，调试接口和硬件抽象也常被考查 |

M2M、鸿蒙等题目重点不是背产品名称，而是识别“感知/采集—通信—处理分析—决策或控制”的链路，以及题干描述的嵌入式约束。遇到实时调度题，先找截止时间、优先级和是否抢占，再判断算法是否满足强实时要求。
